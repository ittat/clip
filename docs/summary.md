# 分层剪辑器 · 设计摘要

> 依据：设计文档 v0.2（`docs/design.md`）、上岗考试题库 v0.7（`docs/exam.md`）· 2026-11-26 · 阶段 0 已完成

## 一句话

**一个以“意图编译器”为核心的视频剪辑器。** 工程拆成多层可读文本：上层写决策，下层由程序编译出来。人和 AI 都能改任意一层；AI 通过一套与模型无关的接口参与编辑，人随时可以完全接手。

## 要解决的问题

| 目标 | 怎么做到 |
|---|---|
| **O1** AI 能读懂素材和项目状态 | 素材入库时理解一次并缓存；分层视图；只给 diff |
| **O2** 省 token | 读“意义”不读帧；一行一个节拍，3 分钟片约 1–2k token；生成类素材根本不用看 |
| **O3** 人始终能接手 | AI 没有隐藏状态；底层是完整的专业时间线；AI 没做完的事都在待决队列里 |
| **O4** 不绑定模型，强弱都能用对 | 系统负责合法性，模型只做选择题；上岗考试测出能力再授权 |

## 核心思想（第一性原理）

1. 剪辑的价值在**决策**（用哪段、放哪），像素和时间码只是执行结果
2. **“看”是一次性成本**：入库时理解，之后只读意义
3. **聪明放在系统里**：能确定的事交给程序，模型只在合法选项里选
4. **每条事实只有一个主人**
5. **可预测比最优更重要**：求解器像编译器，不像优化器
6. **人的注意力最贵**：只在真正影响结果时才问人
7. **记忆存在工程里，不存在模型里**

## 架构

```
L4 意图     目标、时长、风格、禁区          ┐ 选择型编译：系统召回 + 排序，
L3 结构     段落、节拍、作用、预算          │ AI / 人 / 规则只做挑选
L2 内容     哪句话、哪个镜头、哪段音乐      ┘
L1 时间线   帧级多轨（兼容 OTIO）           ← 确定型编译：弹性求解，不用大模型
L0 渲染     像素
```

- **锚点一律用素材坐标**（词、镜头、事件、拍子、标记、素材内偏移），不用时间线时间码，所以上层怎么改都不会错位
- **旁白/TTS**：文字是真相源，合成音频像实拍一样入库；TTS、配乐、生图走同一条“描述 → 生成 → 锁定 → 入库”管线
- **纯画面素材**：用事件、拍子、人工标记做锚点；用结构化“画面简述”代替旁白做匹配

## 四个关键机制

**1. 弹性求解（L2→L1）**
每个元素声明自己能伸缩多少（旁白几乎不能，停顿最能），像 TeX 排版一样求解。代价按 10 项**字典序**比较：
`硬约束 > 人工锁定 > 意图 > 改意思 ┃ 声明预算 > 跨区 > 语速 > 裁剪 > 停顿 > 惯性`
前 4 项改变决定，只能上报；后 6 项编译器自动处理。**编译器只调时间，不改意思。**

**2. 确定性**
整数刻度 flicks、禁用浮点和无序容器、求解器是纯函数、外部生成由锁文件冻结。三个要求：**可复现、局部、有惯性**，全部写成 CI 测试。

**3. 所有权：上提 / 补丁 / 冻结**
人在时间线上改一处，系统先尝试**无损上提**到上层；表达不了就存成挂在语义锚点上的**补丁**；改得多可以**冻结**整段。一次修改永远只是局部事实，**规则必须显式创建**（`rules.yaml`），系统和 AI 都不能自己把例子推广成规则。

**4. 人机协作**
所有改动都是带作者的**变更集**，按风险分级授权（低风险自动、中风险待审、高风险必须确认）。人和 AI 共用一个**待决队列**。AI 无状态，换模型只需 `onboard()` 读工程。

## AI 接口

**8 个工具**：`onboard` `view` `query` `inspect` `propose` `commit` `queue` `lease`
**11 个动词**，目标全部用语义 ID，没有时间码运算。每次返回都附“下一步菜单”：强模型自己组合，弱模型从菜单里选。转写、画面描述都是数据，不是指令。

**没有 AI 也能编译**：全部按候选第 1 名走，得到一版保底粗剪。模型强弱只影响在保底之上做得多好。

## 上岗考试

28 道题，分 T0 引导 / T1 低风险 / T2 中风险 / T3 结构 四档，另有 X 陷阱题。
- **不改坏**一票否决（5 次都要过）；**听得懂**每档 ≥80% 才开放；**做得好**只作参考
- 机器判分，授权环节不用模型打分；干扰器覆盖式分配，考试可复现
- 小模型失败率高的题，先怀疑接口而不是模型

## 技术选型

桌面端优先 · Rust 核心（无界面也能完整运行）· Tauri 外壳 + 原生预览 · FFmpeg · OpenTimelineIO 互通 · 独立 Python 分析服务（ASR、镜头、描述、节拍）· MCP + CLI 接入

## MVP 路线

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| **0 无界面内核** ✅ | 模型、存储、求解器、编译器、CLI | 17 个黄金用例三平台通过；改一个字只影响 1 个区 |
| **1 AI 接入**（3 周） | 8 个工具、变更集、待决队列、上岗考试 | 强弱模型损坏率都是 0；“缩短 S2” < 5k token |
| **2 人类接手**（4 周） | 脚本视图、简化时间线、上提补丁、冻结、OTIO 导出 | AI 中途停掉人能做完；人改 10 处 0 处丢失 |

样例：混合解说片（地球流水线的旁白 + 地球基座生成器 + 10–20 个实拍 B-roll）。
**重点指标**：人手动修改后，能上提的比例。如果大部分只能变成补丁，说明 L2 表达力不够。

## 主要风险

- 上提覆盖不够，补丁泛滥 → 监控上提比例
- 拖动预演达不到 16ms → 增量求解 + 代理文件；与阶段 0 并行验证
- 候选召回取决于入库描述质量 → 描述格式固定（景别、主体、动作、环境）
- 审阅疲劳 → 变更集按段落拆小、抽检
