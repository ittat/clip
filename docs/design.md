## 0. 一句话定位

**一个以“意图编译器”为核心的视频剪辑器。** 工程被分成多层可读文本：上层描述决策，下层由程序编译生成。人和 AI 都可以在任意一层修改。AI 通过一套与具体模型无关的接口参与编辑，人随时可以完全接手。

### 四个目标

| # | 目标 | 落点 |
|---|---|---|
| O1 | AI 能读懂任何素材和项目状态 | 入库时理解素材；分层视图；diff |
| O2 | 尽量省 token | 读意义不读帧；按需抽帧；生成类素材不用看 |
| O3 | 人始终能接手 | AI 没有隐藏状态；L1 是完整的专业时间线；待决队列 |
| O4 | 不绑定模型，强弱模型都能用对 | 接口兜底；选择题化；上岗考试 |

---

## 1. 第一性原理

1. **剪辑 = 根据意图，对素材做选择、排序和变换。** 有价值的是决策，像素和时间码只是执行结果。
2. **视频信息量大，但意义稀疏。** token 成本取决于 AI 在哪个抽象层工作，跟视频长短关系不大。
3. **“看”是一次性成本。** 素材入库时理解一次，结果永久缓存。
4. **聪明放在系统里，不放在模型里。** 能确定的事交给程序，模型只在合法选项中做选择。
5. **每条事实有且只有一个主人。**
6. **时间轴跟着最不能伸缩的元素走。**
7. **可预测比最优更重要。** 求解器要像编译器，不要像优化器。
8. **AI 的产出便宜，人的注意力很贵。**
9. **记忆存在工程里，不存在模型里。**

## 2. 分层架构

```
L4 意图    目标、受众、时长、风格、禁区
L3 结构    段落、节拍、作用、时长预算
L2 内容    每个节拍用哪句话、哪个镜头、哪段音乐、哪条字幕
L1 时间线  帧级多轨（兼容 OpenTimelineIO）
L0 渲染    像素
```

- **上层编译出下层**，人和 AI 都能在任意一层修改
- **L4→L3、L3→L2：选择型编译**。系统负责召回和排序，AI、人或规则只做挑选（详见 §5）
- **L2→L1：确定型编译**。完全由程序完成，不用大模型
- 每层只存**这一层的决策**，上层只引用语义单位，不写时间码

### 系统分层

```
交互层：GUI（大纲/脚本/时间线/预览）｜ MCP ｜ CLI
指令层：统一的操作语法 + 变更集
模型层：分层工程文件 + overrides + rules + 待决队列 + 锁文件
媒体层：素材 + 媒体索引（入库时生成）
渲染：合成器（预览和导出共用）
```

## 3. 数据模型

### 3.1 格式原则
1. 一个工程 = 一个文件夹，每层一个文本文件，可以 diff，可以用 git 管理
2. ID 永久有效、不复用、带类型前缀
3. 只引用，不复制
4. 声明和结果分开放（类似 `package.json` 和 lock 文件）。**源文件用 YAML**（方便人写）；**`build/` 里的产物一律用规范化 JSON**（键排序、固定缩进、UTF-8、末尾换行），保证逐字节比对稳定
5. 每个节点都带来源标记 `by: human | ai:<name> | compiler`，以及 `lock`
6. **锚点必须用素材坐标，不能用时间线坐标。** 素材文件不会被改，素材里的位置永远不变；时间线上的时间会随编译变化。词只是素材坐标上一种“带名字的刻度”，画面同样有自己的刻度（见 §3.3）

### 3.2 工程目录

```
project/
├ project.yaml       工程参数：帧率、采样率、求解器版本（帧偏移 `+2f` 的换算依据）
├ AGENTS.md          给 AI 的说明书（目标、风格、尚未结构化的偏好）
├ intent.yaml        L4
├ structure.yaml     L3
├ content.yaml       L2
├ narration.yaml     旁白稿（创作类声音的真相源）
├ voices.yaml        声音包
├ generators.yaml    生成素材的源描述
├ overrides.yaml     人工补丁（局部事实）
├ rules.yaml         规则（带范围的声明，显式创建）
├ queue.yaml         待决队列（阶段 1 由协作层根据求解报告生成）
├ history/           变更集
├ media/index.yaml   媒体索引
├ frozen/<段落>.json 冻结段（`clip freeze` 生成；所有权归 L1，是源文件）
├ locks/
│ ├ tts.lock.json    随机型生成结果的锁（阶段 0 为 TTS 替身）
│ └ solver.lock.json 求解器版本锁（`clip lock accept` 生成）
└ build/             L1 时间线、求解报告（规范化 JSON，随时可重新生成）
```

**读写边界**（v0.2）：
- 编译器只读源文件、只写 `build/`。`build/` 不会被当作输入读取（G-02 检查）
- 锁文件放在 `locks/` 而不是 `build/`：随机型生成的结果锁定后无法重新生成，而 `build/` 必须随时可以重新生成
- `frozen/` 和 `locks/solver.lock.json` 只能由对应命令写入，编译器从不写
- 集合一律写成以 ID 为键的映射；列表只用于顺序有意义的地方（`sequence`、`beats`、`visual`、`alt`、`words`）。“顺序无关”只针对映射的键顺序
- 引用一律写完整前缀（`shot:A.1`，不写 `A.1`）

### 3.3 语义 ID

| 前缀 | 对象 | 示例 |
|---|---|---|
| `w:` | 实拍语音中的词 | `w:A.1042` |
| `n:` | 旁白句 / 词 | `n:S2.1`、`n:S2.1.w5` |
| `shot:` | 镜头 | `shot:A.47` |
| `seg:` | 镜头内片段（长镜头按运镜/内容变化切分） | `seg:B.12.2` |
| `ev:` | 画面 / 声音事件（动作结束、运动峰值、入画出画、运镜停止、撞击声、欢呼） | `ev:B.12.3` |
| `bar:` | 音乐刻度（小节.拍） | `bar:M1.17.b3` |
| `mk:` | 标记，与词同为一等锚点；人或 AI 都可以打，`by: ai` 的标记优先级较低（§9.1） | `mk:B.12.goal` |
| `@` | 兜底：素材内相对时间，仍然稳定 | `shot:B.12@+2.40s` |
| `S` | 段落 / 节拍 | `S2`、`S2.b1` |
| `gen:` | 生成素材 | `gen:img.S2.1` |
| `ov` / `q:` / `cs:` | 补丁 / 待决项 / 变更集 | `ov7`、`q:17`、`cs:042` |

**锚点写法统一**，语音和画面没有区别：
```yaml
- id: ov9
  anchor: {at: ev:B.12.3, offset: -2f}   # 动作结束前 2 帧
  patch: {cut: in}
```

**稳定的语义 ID 是整个系统的地基。** 上提、补丁锚点、视图联动、AI 引用都依赖它。

### 3.4 各层示例

```yaml
# intent.yaml (L4)
goal: 讲清楚 X 为什么失败
duration: {target: 180s, tol: 10%}
pace: fast
must: [w:A.1042..1077]
forbid: [血腥画面]
```

```yaml
# structure.yaml (L3)
- {id: S2, role: argument, budget: 40s, mood: 上扬, by: ai}   # budget 是“声明”；不写则由求解得出，结果只写进 build/
```

```yaml
# content.yaml (L2)
- id: S2.b1
  voice:  {narration: n:S2.1, fit: rigid}
  visual:
    - {shot: A.47, role: a-roll}
    - {shot: B.12, role: b-roll, fit: fill, from: n:S2.1.w5}
  subtitle: {from: voice}
  music: {cue: M2, level: 0.6, fit: bars}
  pause: {after: 0.4s, flex: 0.2..0.8s}
  clock: auto
```

```yaml
# overrides.yaml
- id: ov7
  anchor: {beat: S2.b1, at: n:S2.1.w5}
  target: visual[1]
  patch: {exposure: +0.3, offset: +4f}
  by: human
```

```yaml
# media/index（节选）
words: [{id: 1042, t: 63.20, txt: 其实}, ...]
shots: [{id: A.47, in: 61.0, out: 70.4, desc: 中景 A 坐窗前, focus: .9, shake: .1}]
cut_points: [w1049.end, w1077.end]
```

L1 采用兼容 OTIO 的格式，**每个片段都带 `origin` 反向指针**（例如 `origin: S2.b1`），上提靠的就是它。

### 3.5 旁白 / TTS

- 声音有两种来源：**拾取**（实拍，从素材池里选）和**创作**（TTS，先写文字再合成）
- 对 TTS 来说，**真相源是文字，音频是编译产物**
- 合成出来的音频**和实拍素材一样入库**，进行强制对齐并分配词级 ID。下游不区分声音是录的还是合成的

```yaml
# narration.yaml
- id: n:S2.1
  text: "其实，这个计划从一开始就{注定|zhu4ding4}失败了。[停0.3]"
  voice: narrator
```
- 标记只保留三种：停顿、强调、读音，与 TTS 厂商无关
- `voices.yaml` 是声音包，例如 `narrator: {provider: mimo, voice: 小吴, rate: 1.0}`
- 改字时以句子为单位重新合成，用文本 diff 保留未改动词的 ID

### 3.6 给 AI 的压缩视图

存储格式 ≠ AI 视图。默认一行一个节拍：
```
S2.b1 | A「其实…失败了」| A.47+B.12 | 8.2s
S2.b2 | B「数据显示…」  | 图表C     | 6.0s
```
3 分钟的片子大约 30 行、1–2k token。

## 4. 媒体层：入库即理解

导入素材时，由本地模型一次性算好，结果永久缓存，并记录分析模型的版本：
- 镜头切分、逐词转写（含强制对齐）、说话人、人脸和物体
- 每个镜头一句话描述、画质评分（虚焦、抖动、曝光）
- 可剪点：自然停顿、动作结束点
- **画面锚点**：长镜头内片段、画面事件、声音事件，各分配永久 ID；检测模型版本写进索引，升级不改变已有锚点
- **入库描述格式固定**：`{景别, 主体, 动作, 环境}`，与 L2 的画面简述同一结构
- 人或 AI 可随时打**人工标记**（如“进球瞬间”），弥补检测不准，并用于区分大量相似事件中的关键事件
- 语义向量（支持 `find_shots("近景说话")`）
- 音乐：节拍和小节线

AI 读的是“可检索的素材库”。只有在选择有歧义时，才看抽帧拼板图（图上印着镜头 ID 和时间）。

## 5. 选择型编译（L4→L3→L2）

### 5.1 本质：选择分三步，只有一步需要判断

```
召回（有哪些可选） → 排序（哪个更好） → 挑选（选哪个）
```

| 步骤 | 性质 | 谁来做 |
|---|---|---|
| 召回 + 硬过滤 | 什么是合法的 | 系统（确定） |
| 排序 | 什么有依据地更好 | 系统（确定，附理由） |
| 挑选 | 什么最符合意图 | AI / 人 / 规则 |

弱模型容易错在开放式生成，很少会在几个附了理由的选项里选错。所以**系统做前两步，模型只做第三步**。

**创作也归到挑选**：旁白文字、生成素材的描述属于创作。创作结果先过校验（时长估算、must 覆盖、forbid），再生成多个变体，作为候选进入同一个挑选流程。

### 5.2 槽位：上层给下层出题

```yaml
slot: S2.b1.visual[1]
need:
  role: b-roll
  about: n:S2.1.w5..w12          # 这段旁白在说什么；无旁白时见 §5.10
  mood: 上扬                     # 来自 L3
  dur: {min: 3.2s, ideal: 4.5s}  # 来自求解器
  avoid: [已用镜头, forbid]
```

### 5.3 召回与硬过滤
- **多路召回**，按 ID 去重：语义向量（旁白 ↔ 镜头描述）、实体匹配（人名、地名、物体）、时间邻近（与 A-roll 同时段）、规则（同场景其他角度）
- **硬过滤**，不合格的直接不出现：forbid 内容、画质低于阈值、时长不够且无法接续、已被使用、授权缺失、`rules.yaml` 中的禁用规则

### 5.4 排序：粗分档 + 字典序

```
rank = (语义匹配档, 节奏契合档, 时长适配档, 画质档, 与相邻镜头的连续性, 新鲜度, ID)
```
- 不用加权总分，原则与求解器一致：可解释、可复现
- **节奏契合档**：镜头里的运动峰值或事件能否对上槽位里的强拍。确定性计算，不需要模型看画面；在蒙太奇段落中尤其关键
- **粗分档**（高/中/低；刚好/需接续/需慢放）：分析模型小幅更新不会让排名乱跳
- 每个候选附带由档位生成的理由

返回给模型的候选卡（5 个约 150 token）：
```
S2.b1.visual[1] 候选（top 5）
[1] shot:B.12 废弃厂房远景 | 匹配高 | 4.8s刚好   | 画质高
[2] shot:B.31 生锈机器特写 | 匹配高 | 3.0s需接续 | 画质高
[3] shot:C.04 空旷车间     | 匹配中 | 6.2s刚好   | 画质中
gap: [1] 与 [2] 同档，差在时长适配
```
只有同档难分时，才 `inspect` 一张印着候选 ID 的拼板图。

### 5.5 挑选：按差距和能力分流

| 情况 | 谁来选 |
|---|---|
| 第 1 名高出一整档 | 规则直接选 top-1（`decidable: rule`） |
| 前几名同档 | AI 选；弱模型只答序号 |
| 最高只到“低” | AI 改写查询 / 进队列问人 / 提议生成素材 |

| 权限档 | 挑选能力 |
|---|---|
| T0/T1 | 只能从 top-k 中答序号 |
| T2 | 可要更多候选、改写查询条件 |
| T3 | 可自定义结构、直接引用索引中任意 ID（`propose` 时校验存在） |

**没有 AI，系统也能编译**：全部按 top-1 走，得到一版“保底粗剪”。**下限由系统保证**，模型强弱只影响在保底之上做得多好。

### 5.6 L4→L3：结构也是挑选
- 按片型准备**结构骨架**（问题→论点→例证→结尾、时间线叙事、清单体……），每个骨架带段落作用和默认权重，直接接上 §6.6 的规划模式
- 弱模型：选一个骨架，再填每段的一句话目标
- 强模型：可组合或自定义骨架，但要过结构校验（必须有开场和结尾，must 内容有着落）
- 与地球流水线模板编辑器“AI 只从已安装的包里选”是同一模式

### 5.7 选择之间的依赖：固定顺序贪心 + 全局检查
- 不做全局优化（理由同求解器）
- 按固定顺序逐个挑选：段落 → 节拍 → 槽位。前面的选择进入后面的“已用”和“连续性”条件
- 全部选完后跑**全局检查**：重复镜头、跳切、同一景别连续过多、节奏单调。有问题进待决队列，附替换候选

### 5.8 惯性：选过的就是事实
- 选定结果作为事实写进 L2，带 `by`
- 上层重新编译时，**原选择仍合法就保留**，不重新排序挑选
- 只有原选择失效（被过滤、槽位时长不可行）才重新挑选，并在报告中写明原因

### 5.9 偏好积累
- 人拒绝时写的理由（如“不要航拍”）转为**硬过滤**或**排序中新增的一档**（如“偏好近景”），写进 `rules.yaml`（尚不能结构化的先写进 `AGENTS.md`）
- **不自动学习排序权重**：自动学习会让同一工程在不同时间排出不同结果，违背可复现。偏好必须显式、可见、可改

### 5.10 纯画面段落（D-6）

**问题拆分**：纯画面素材的“锚点问题”已由素材坐标解决（§3.1、§3.3）；真正要设计的是**语义问题**：没有旁白时，槽位的 `about` 从哪来。

**`about` 的来源**（按可靠程度）：

| 来源 | 内容 | 例子 |
|---|---|---|
| **画面简述**（L2 新字段） | AI/人写的结构化描述，属于创作，要过校验 | `{景别: 远, 主体: 城市, 动作: 车流, 情绪: 平静}` |
| L3 段落目标 | 段落的一句话目标 | “展示城市从清晨到夜晚” |
| 音乐段落特征 | 能量、情绪、段落位置 | 副歌 → 高能量 |
| 镜头语法 | 序列规则 | 远 → 中 → 近；建立镜头在前 |
| 前后连续性 | 相邻镜头的主体、方向、色调 | 运动方向一致 |

画面简述与入库描述同一结构，匹配是**字段对字段**，不是自由文本对自由文本：弱模型写得出，系统比得准。

```yaml
- id: S4.b2
  visual:
    - {brief: {景别: 近, 主体: 手, 动作: 拧紧螺丝}, fit: fill, cut_on: bar:M1.21.b1}
  music: {cue: M1, fit: bars}
  clock: music
```

**序列模板**（给弱模型；延续“结构也是挑选”）：
- **铺垫型**：建立远景 → 2–3 个细节 → 高潮落在强拍
- **对比型**：A/B 交替，逐渐加快
- **时间推移型**：同一主体按时间顺序

弱模型只选模板，再给每格写简述或用默认值。没有 AI 时，系统按“音乐能量 + 镜头语法”排出保底蒙太奇，**下限依然由系统保证**。

## 6. 时钟与弹性编译（L2→L1）

### 6.1 弹性模型（盒子 + 胶水）
每个元素声明：自然长度、可伸、可缩。

| 元素 | 弹性 |
|---|---|
| 外部限制（广告时长、平台上限） | 绝对固定 |
| 同期动作 | 不能伸缩 |
| 人声 / 旁白 | 几乎不能（语速 ±8%） |
| 音乐 | 不能拉伸，可以按小节剪 |
| B-roll | 弹性大 |
| 停顿 | 弹性最大 |

`clock: auto` 时的默认优先级：**外部限制 > 同期动作 > 人声 > 音乐 > 画面**。同一个片子里可以混用不同的时钟。

### 6.2 节拍内求解
1. 先摆放硬元素，节拍时长 = 最长的硬元素 + 呼吸停顿
2. 弹性画面填满剩余时长：优先在可剪点裁剪 → 不够就接候选镜头 → 最后才慢放（≤20%）
3. 音乐吸附：段落切换点吸附到最近的强拍，误差由停顿消化（±0.3s）

### 6.3 超预算时逐级处理
处理顺序**由 §7.3 的代价公式直接推出**（代价低的先用）：

压缩停顿（9）→ 裁剪弹性画面（8）→ 微调语速（7）→ 向相邻区借时间（6）→ 偏离已声明的段落预算（5）→ **编译器停手，向上层报冲突**（3、4 项）

> v0.1 曾写作“停顿 → 语速 → 裁剪”，与代价公式不一致，已按公式修正：裁剪 B-roll 比改人声语速更不易被察觉。

**编译器只调时间，不改意思。** 这条规则对应代价公式中第 4、5 项之间的分界线。

**实现细节（v0.2）**：
- 每一步按各节拍的可用量**按比例分配**，余数按成片顺序逐个补 1 flick，结果确定
- 纯画面节拍的主体最短压到 1 秒（素材更短时取素材长度）
- 语速最多 +8%：旁白最短时长向上取整，保证真实速度不超过上限；`speed_ppm` 四舍五入，所以上限显示为整 1,080,000
- 语速变化时，画面的入画时间按同样比例缩放
- 语速调整在阶段 0 只用 `speed_ppm` 预览，报告列出 `tts_resynth_needed`；真正重新合成在阶段 1 的生成管线
- `fit: fixed` 必须写 `len`；固定长度超出素材记为第 1 项

### 6.4 混用的难点
- 时钟交接处自动生成 J/L 切，交接点选在双方都有停顿的位置
- 音乐是挂在段落上的独立区间，只在区间内重新吸附，必要时在小节线上补一小节或剪掉一小节

### 6.5 人的拖动
人拖动片段长度 → 记为局部事实 `fit: fixed 3.2s, by: human`（只管这一处，见 §9.1）。人的操作和编译器用的是同一套约束语言。

### 6.6 段落预算：L4 → L3（D-4）

**时长有两个来源**：自上而下（L4 总时长）和自下而上（硬元素决定的自然长度）。预算是两者协调的结果，**默认不是一条独立的事实**。
- 未声明的预算 = 求解结果，写进 `build/`
- 只有人或 AI 明确写下的预算，才是 `structure.yaml` 里的声明

**段落也是盒子 + 胶水**：自然长度 = 各节拍自然长度之和；可伸缩量 = 内部停顿、画面、语速余量之和；L4 总时长是“行宽”。**同一个求解器在段落层再跑一遍**，不另设分配算法。

| 模式 | 时机 | 分配方式 |
|---|---|---|
| 规划 | 还没有内容（从脚本做粗剪） | 按段落作用的默认权重拆分；整数刻度 + 最大余数法取整，余数按 ID 顺序分配。结果只是给 AI 的目标 |
| 拟合 | 已有内容 | 见下 |

**拟合规则**：
```
Σ自然长度 在 [目标 ± 容差] 内 → 不调整，各段用自然长度
超出容差 → 差额 Δ 按代价公式消化：
  ① 变化段落先用自己的弹性（9→8→7）
  ② 再由相邻段落由近到远分摊，有上限（6）
  ③ 仍消化不了 → 上报（3：L4 意图偏离），可选：删内容 / 放宽目标
```

- **L4 容差就是保证局部性的全局缓冲。** 每次都精确拉到目标时长，会让改一个字牵动全片
- 需要精确时长（如 15 秒广告）时写 `fit: exact`，容差为 0，代价是每次改动都影响全片
- AI 只需要设总时长，不需要会算各段预算
- TTS 生成前自然长度只能估算（中文约每秒 4–5 字）；偏差在容差内不引起重排，所以估算不必很准

### 6.7 全片偏短：拉伸（v0.2）
总长低于 L4 下限时，和压缩对称、代价低的先用：
1. 停顿拉到 `flex` 上限（第 9 项）
2. 纯画面节拍的主体变长，画面靠慢放撑满（第 8 项，≤20%）

- **不放慢语速**：旁白放慢比加快更容易被听出来
- 分两轮：先只在声明预算以内拉；不够再拉其余部分（超出预算记第 5 项）
- 拉长停顿不能让弹性画面撑不满：可拉伸量受“画面慢放到上限后能撑多长”约束
- 仍不够的部分记第 3 项，报 `intent_under`，方案为“加内容 / 放宽 L4”
- 规划模式（还没有内容时按 `role` 权重分配预算）推迟到阶段 1 的粗剪任务

### 6.8 音乐的位置（v0.2）
- 音乐从**第一个用到它的节拍**开始，从素材的 `first_bar` 起播；`music.start` 可以让它延后进入（只有第一个节拍里的值生效）
- `fit: bars` 时，播放长度向下取整到整小节；报告里的 `tail_gap` 是最后一个用到它的节拍结束点和音乐结束点的差
- 段落切点吸附到强拍、片尾对齐小节线见 §6.9；吸附后 `tail_gap` 通常为 0

### 6.9 段落切点吸附强拍、片尾对齐小节线（D-7，v0.2.1）
在时长求解（含 L4 压缩/拉伸）之后、借用之前执行：
- **候选**：音乐覆盖范围内（严格在音乐起点和最后一个用到它的节拍结束点之间）的每个段落切点，以及每段音乐最后一个用到它的节拍的结束点。同一个节拍两者都是时，按片尾处理
- **目标**：段落切点 → 最近的强拍（4/4 为第 1、3 拍）；片尾 → 最近的小节线。只在音乐实际有的范围里找
- **做法**：调整切点前一个节拍的**停顿**，让切点落在目标上。按成片顺序逐个处理，每次都按当前状态重新排布
- **限制**（任一不满足就不吸附，原因写进报告 `snaps[].status`）：调整量 ≤ ±0.3s；新停顿在 `flex` 区间内；拉长时不能让弹性画面撑不满；拉长时不能超出声明预算；不能让全片超出 L4 区间；切点前是冻结段时不吸附
- 全片有阻塞冲突（`intent_over` / `intent_under`）时，一律不吸附（`conflict`）
- 调整量计入第 9 项（停顿偏离）。这是一个“软目标”：代价公式本身不偏好吸附，吸附作为确定的后处理执行
- 冻结段里的节拍不算“用到”音乐

### 6.10 截取画面对齐可剪点（D-8，v0.2.1）
- `media/index.yaml` 的镜头可以写 `cut_points`（素材坐标，必须在 in/out 之间）
- 弹性画面需要截取（`fill: cut`）时，**整体平移所用的素材窗口（slip）**：出点挪到最近的、在默认出点之后的可剪点上。**时间线上的时长和位置都不变**，所以不影响求解
- 平移发生在补丁之前：挂在素材偏移、事件、标记上的锚点会跟着画面走
- 报告 `slips` 记录每次平移（可剪点、平移量、前后的素材入点）

## 7. 求解器的确定性

### 7.1 三个要求
**可复现**（同样输入，同样输出）· **局部性**（改一处，只影响附近）· **惯性**（多解时选和上次最接近的）

### 7.2 消除不确定性
- 时间一律用整数刻度 **flicks（1/705,600,000 秒）**，只在输出时换算成帧
  - 能整除 24/25/30/50/60fps、23.976/29.97/59.94fps 的帧长，以及 44.1k/48k 的采样间隔；i64 可表示约 414 年
  - v0.1.6 之前用 1/48000 秒：29.97fps 一帧是 1601.6 个刻度，帧边界无法精确表示，已废弃
  - 时长字符串（`0.4s`、`+2f`）按十进制精确解析成刻度，不经过浮点；`f` 按 `project.yaml` 的帧率换算
- 所有处理按稳定 ID 排序，不受书写顺序影响
- 可以并行计算，但合并时按固定顺序
- 外部生成的结果由锁文件冻结
- 不用通用优化器（ILP/SAT）

### 7.3 代价：字典序比较（D-1 已决）

**每一项的位置，取决于被改动的事实归谁所有、层级多高。** 越接近人的原始决定，代价越高。

```
cost = (
  1  违反硬约束数          # must / forbid / 平台上限
  2  人工锁定偏离          # 归人所有的事实（含人声明并加锁的预算、人设定或批准的规则）
  3  L4 意图偏离           # 总时长超容差、节奏等
  4  改意思的程度          # 删句、改写
  ─────── 编译器自动处理的边界 ───────
  5  偏离已声明的段落预算  # 仅限声明；推导出的预算代价为 0
  6  跨区影响              # 向相邻区借时间时，被波及的区数
  7  语速偏离
  8  画面裁剪 / 变速量      # 含 §6.2 的慢放
  9  停顿偏离
  10 与上次结果的差异      # 只在平局时起作用
)
```

- 排在前面的项无限优先于后面的项
- **1–4 项会改变决定，只能上报；5–10 项只调时间，编译器可自动处理**（5 项的偏离写入求解报告）
- 推论：**进入待决队列的冲突，选项只会来自第 1–4 项**。第 5–10 项的手段在上报前已被编译器用尽，不会再作为选项出现
- “放宽预算”不再是一项，而是按情况落在不同位置：全片仍在 L4 容差内 → 第 5 项；超出容差 → 第 3 项
- 平局时：先选与上次差异最小的，再选 ID 字典序最小的

### 7.4 局部性：分区 + 防火墙
- 按硬锚点分区：人工锁定、段落边界、音乐小节线
- **“先区内、后借用”由代价公式推出**：跨区影响（第 6 项）排在语速、裁剪、停顿之前，所以编译器会先用完区内余量才去借
- 借用的方向和数量有上限；借不到就上报
- 增量编译：只重新计算被改动的区，其他区逐字节复用上次结果

### 7.5 无解
按固定顺序逐级放松约束，报告**最小冲突集**和可选方案，作为一道选择题进入待决队列。

**实现（v0.2）**：
- 最小冲突集：把各元素在弹性用尽时的最短长度从大到小累加，刚好超过上限为止（元素最少）。冻结段整体算一个元素
- 方案推荐顺序：删句（4）< 放宽 L4（3）< 删开场/结尾的句子 < 动人工锁定（2）
- 含 must 词的句子永远不会作为删除选项；`role` 为 `opening` / `closing` 的段落里的句子仍会列出，但标 `protected_role`、不被推荐（只影响推荐，不改代价公式）
- 冻结段里的句子不能删，只能提议 `unfreeze`

### 7.6 验证（CI 必跑）
幂等 · 顺序无关 · 局部性（改动影响的区数有上限） · 黄金样例逐字节比对。
求解器版本写进锁文件，升级后旧工程不会悄悄变样，迁移需要用户显式确认，并先给出差异预览。

**实现（v0.2）**：
- 每个区有一个**区哈希**：段落报告（去掉绝对起点）+ 节拍报告 + 补丁和规则之后的最终片段（时间相对段落起点，音乐除外）。段落整体平移不改变哈希
- `clip lock accept` 把当前求解器版本和各区哈希写进 `locks/solver.lock.json`
- 版本不一致时，编译照常进行，报告给出非阻塞冲突 `solver_changed`，列出哈希不同的区；锁文件**不会自动更新**
- `clip lock check`：版本和各区哈希都一致时退出码 0，否则 1
- 局部性按区比较“相对内容”：段落整体平移不算变化

## 8. 生成素材的统一管线

```
素材 = f(源描述, 参数, 模型版本, 随机种子)
```

| 类别 | 例子 | 冻结方式 |
|---|---|---|
| 确定型 | 图表、地图动画、字幕卡 | 只存源描述，产出是可丢弃的缓存 |
| 随机型 | TTS、AI 配乐、生图、生视频 | 锁定产出本身，产出是需要备份的资产 |

**五步**：描述 → 解析（合入风格包、声音包、服务商，算出哈希）→ 生成（命中缓存就复用）→ 锁定 → 入库

```yaml
- id: gen:img.S2.1
  kind: image
  spec: {subject: 废弃的工厂, framing: 远景}
  style: @theme            # 风格来自主题包，不写在提示词里
  slot: {aspect: 16:9, dur: fill}
  variants: 3
  pick: 2
```

- **风格和内容分开**：提示词只写主体，风格由主题包统一注入
- **时长的依赖关系**：生成器分为生产者（硬，如 TTS）和消费者（软，如背景音乐、空镜）。编译分两阶段：生成硬素材 → 求解时间 → 生成软素材。消费者不能反过来改时长
- **占位卡**：还没生成完的素材显示为占位卡，不阻塞人剪辑；生成前先预估成本
- **反向检查**：TTS 用 ASR 转回文字比对；音乐检查节拍和响度；生图由本地小模型写描述再和 spec 比对；图表只校验数据
- **服务商就是一个包**，每个包带一份能力清单，缺的能力由编译器补齐（例如本地做强制对齐）。换服务商不会自动覆盖已锁定的素材
- 每个产出都记录来源元数据（模型、版本、是否 AI 生成、授权信息）

## 9. 所有权：上提、补丁、冻结

**默认派生：上层是默认主人，L1 是默认产物。每条事实的主人唯一，但可以在层之间显式转移。**

| 状态 | 主人 | 上层重新编译时 | 界面标记 |
|---|---|---|---|
| 编译 | 上层 | 自由重新生成 | 无 |
| 补丁 | 上层 + 锚定补丁 | 重新生成后按锚点把补丁贴回去 | 图钉 |
| 冻结 | L1 | 不碰，当作硬盒子 | 锁形边框 |

人在时间线上的操作，系统按顺序归类：
1. **上提**：能用上层语言**无损**表达的，直接改写上层（范围只限这一处，见 §9.1）
2. **补丁**：表达不了的，存成挂在语义锚点上的补丁
3. **冻结提示**：同一区补丁过多（比如 5 个）时，提示“要冻结这段吗？”

- **失锚**：锚点没了的补丁不会被静默丢弃，而是进入待决队列
- **冻结粒度**：暂定**按段落**（见 §18 D-2）
- **冻结区不是 AI 的盲区**：系统反向入库，生成一段只读的 L2 摘要。AI 想改冻结区，只能提出解冻建议
- **反编译**：导入 FCPXML/EDL 时，整个工程是全冻结状态，AI 可以立即通过只读 L2 读懂它，之后逐段解冻并上提，把老工程慢慢迁移到分层模式

### 9.1 上提的两个维度（D-3）

**原则：一次修改永远只是一条局部事实。规则必须单独、显式地创建，系统不能替人推断。**

| 维度 | 问题 | 处理 |
|---|---|---|
| 表达层级 | 这条局部事实用哪一层的语言记下来 | §9.1 无损表达 |
| 作用范围 | 只管这一处，还是也管别处 | 默认只管这一处；扩大范围见 §9.2 |

**无损表达**：选一种表达，使重新编译的结果和人现在看到的**完全一样**；满足这个条件的表达里，选层级最高的。
- 不移动人的那一刀，只把它**挂到最近的有名刻度上，再加偏移**，例如 `ev:B.12.3 +2f`
- v0.1.4 的“±3 帧内吸附”会改变人的结果，已废弃

**锚点优先级**：人打的标记（`mk:`, `by: human`）> 事件 > AI 打的标记（`mk:`, `by: ai`）> 拍子 > 词 > 素材偏移
- AI 打的标记排在事件之后：AI 可以补充检测不到的刻度，但不能造出比检测结果更“权威”的锚点

**延迟消歧**：附近有多个刻度且结果相同时，不必现在决定人是冲着哪个切的：
```yaml
anchor: {at: bar:M1.17.b1, offset: 0f}
alt:    [{at: ev:B.12.3, offset: +2f}]   # 另一种解释
```
- 平时按优先级选主锚点，保留原结果
- 以后两个刻度不再重合（例如换音乐、音乐入点平移、剪掉一小节），才进待决队列：“这一刀跟着拍子走，还是跟着动作走？”
- **只有当问题真正影响结果时才问人**

### 9.2 作用范围：默认只改这里

规则有三个来源，都不打断人：

| 来源 | 触发方式 |
|---|---|
| 人主动设定 | 修改后旁边出现轻提示“设为规则？”，点了才生效 |
| 重复检测 | 同一段落内同一种修改 ≥3 次，进待决队列提建议（`judgment`） |
| 拒绝理由 | 人拒绝 AI 改动时写的理由（§11.4） |

AI 也可以提议规则，但必须作为变更集提交，风险等级为中，需人审。**系统和 AI 都不能自己把一个例子升级成规则。**

**范围候选由系统生成**：从例子的共同特征推出，按从窄到宽列出，默认推荐覆盖全部例子的最窄范围，每项写明影响几处：
```
你在 3 处把 B-roll 的切点对到了强拍上。设为规则？
  [1] 仅 S4 段（3 处都在这里）   ← 推荐
  [2] 所有音乐主导的段落（会影响 5 处）
  [3] 全片（会影响 11 处）
  [4] 不用
```

### 9.3 规则：带范围的声明

```yaml
# rules.yaml
- id: r:5
  scope: {section: S4, role: b-roll}
  do: {cut_on: beat.strong}
  by: human
  examples: [ov11, ov12, ov14]   # 来源修改
```

1. **具体优先于一般**：人的局部修改 > 窄规则 > 宽规则 > 系统默认。规则永远不覆盖人的局部修改
2. **对已有内容立即生效，但先预览**：只改归编译器所有的结果；人的补丁、冻结段不动
3. **规则冲突**：先比范围谁更窄；范围相同进待决队列，不按创建时间悄悄决定
4. **撤销**：系统记录规则影响过哪些地方，撤销时全部回退
5. **代价**：违反人设定的规则、或经人批准的 AI 规则，都算 §7.3 第 2 项（人工锁定偏离）
6. **规则可以用于消歧，不能覆盖**：补丁已记录多种解释（`alt`）且解释分开时，规则可以在**这几种解释之间**选一个；不能把补丁移到第三个位置，也不能改补丁的偏移量

### 9.4 补丁的执行语义（v0.2）
- **在求解之后应用，不反过来影响求解**。否则会形成循环：补丁改了片段长度 → 慢放比例变了 → 事件在成片里的位置又变了
- `target` 写成 `S2.b1.visual[1]` 或 `S2.b1.voice`，加载时校验元素存在
- `cut: in` 是“裁头”：片段入点挪到锚点，素材入点按播放速度同步挪动，**每一帧画面留在原来的时间线位置**；被裁掉的部分露出下层轨道。`cut: out` 是裁尾
- 其他键值（如 `exposure`）原样写进片段的 `attrs`，交给渲染器
- 锚点解析全部基于打补丁之前的几何，补丁之间互不影响；按补丁 ID 顺序应用
- 同一镜头被多个片段用到时，优先补丁的目标片段，否则取时间线上最早的
- 主锚点和 `alt` 在时间线上相差**不到半帧**视为重合（`alt_coincide: true`）；分开时报 `anchor_diverged`，按主锚点保留，等人决定
- 找不到锚点报 `unanchored`，补丁不应用、也不丢弃；剪切点不在片段内部报 `patch_out_of_range`
- `mk:` 标记锚点（D-9）：`media/index.yaml` 的 `marks` 表，写法 `"mk:B.12.goal": {shot, at, by}`，`by` 为 `human` / `ai` / `ai:<名字>`。和事件一样按素材坐标解析

### 9.5 规则的执行（v0.2）
阶段 0 支持一种动作：`do: {cut_on: beat.strong}`。
- 范围：`section` / `beat` / `role`，可组合；越具体越优先（节拍 > 段落 > 全片）
- 强拍：每小节第 1 拍；偶数拍号还有中间那一拍（4/4 的第 1、3 拍）。只算音乐实际播放的范围
- 在补丁之后执行：画面入点吸附到最近的强拍，**距离不超过半拍，只向后裁头**（不延长片头），吸附方式和裁头相同，画面帧位置不变
- 不吸附的情况都写进报告：已经在强拍上（`aligned`）、带人工剪切补丁（`patched`）、会露出空白（`would_expose_gap`）、强拍在入点之前（`needs_head_room`）等
- **不碰带人工剪切补丁的片段和冻结段**
- 补丁的两种解释分开、且只有一条规则覆盖它时，规则选落在强拍上的那种解释（`resolved_by`），不产生待决项
- 同样具体的两条规则覆盖同一个片段时报 `rule_conflict`，都不执行

### 9.6 冻结段（v0.2）
- `clip freeze <dir> S1` 把 S1 当前的片段存成 `frozen/S1.json`（时间相对段落起点），`clip unfreeze` 删除它
- 编译时冻结段是**固定长度的硬盒子**：不参与压缩、拉伸、借用，原样输出、只随段落起点整体平移
- 补丁和规则都不碰冻结段里的片段
- 冲突方案里可能出现 `unfreeze`（代价第 2 项），由人决定
- 音乐跨段落，不随段落冻结（D-10 已决）：冻结段里的节拍不参与音乐放置和吸附
- 冻结粒度仍按段落（D-2）

## 10. 人类界面

**界面跟着人当下的思维层级走：讲故事 / 选内容 / 抠细节。**

| 视图 | 对应层 | 主要操作 |
|---|---|---|
| 大纲 | L4 + L3 | 拖段落卡片；看预算条和情绪曲线 |
| 脚本 | L2 | 像编辑文档一样删改句子，改旁白触发重新合成，镜头缩略图贴在页边 |
| 时间线 | L1 | 完整的专业多轨 |
| 素材库 / 候选 | 媒体索引 | 检索；点任意节拍列出可替换候选 |

- **选中状态全局联动**：在任意视图选中一个节拍，其他视图同步高亮
- **画出弹性**：硬元素画成实心块，弹性元素带伸缩纹理，停顿画成弹簧，人工锁定加钉子
- **拖动时实时预演**：半透明显示周围会受到的影响，松手才提交
- **求解报告贴在原位**：比如某个停顿被压到下限，就在弹簧上标一个小黄点
- **预算条**：推导出的预算画成空心，声明的预算画成实心。人拖动预算条 = 声明预算（上提）；点“恢复自动”回到推导值
- **不向用户暴露“层”这个词**
- **默认布局分两种**：专业剪辑师以时间线为主，创作者和新手以脚本视图为主，底层是同一个工程
- 手机或小屏幕上只保留脚本视图和预览

## 11. 人机协作

### 11.1 统一抽象
- **作者**：人、AI-A、AI-B、编译器，地位平等，都带身份标记
- **变更集**：所有改动都打包成变更集（包含 base、intent、ops、impact、risk），人的手动操作是自动提交的变更集

### 11.2 并发
软锁租约 → AI 在草稿分支上工作 → 按事实合并 → 冲突时人优先 → 租约超时自动释放

### 11.3 授权：按风险分级
| 风险 | 例子 | 默认处理 |
|---|---|---|
| 低 | 改字幕错字、响度、压缩停顿、单句 TTS 重合成（成本 < ¥0.1） | 自动接受，事后可撤销 |
| 中 | 换镜头、改旁白措辞、调结构顺序 | 打包成建议，等人审 |
| 高 | 删内容、动冻结区、花钱生成、改意图 | 必须人确认 |
| 禁止 | 违反 must / forbid | 系统直接拒绝 |

信任度按作者单独调；系统统计接受率，可以**建议**提权，但**提权由人决定**；成本预算是硬约束。

### 11.4 审阅
意图一句话 → 影响摘要 → 只播变化区域的对比播放。
拒绝时附的理由先沉淀进 `AGENTS.md`；能结构化的，再由 AI 或人提议转成 `rules.yaml` 里的规则。两份文件分工：
- **`rules.yaml`**：结构化，编译器和候选排序直接执行（过滤、排序档、默认值），可测试、与模型无关
- **`AGENTS.md`**：给 AI 看的自然语言说明：目标、风格、还没法结构化的偏好

防审阅疲劳：连续全部接受后，高风险变更强制要求看对比播放，或者随机抽检。

### 11.5 待决队列
人和 AI 共用一个队列：冲突、失锚、生成失败、AI 提问、解冻建议都进这里。
```yaml
- {id: q:17, type: conflict, question: S2 超出 3.8s,
   options: [A, B, C], recommend: A, blocking: false,
   assignee: any, decidable: judgment}
```
非阻塞项先用保守默认值继续编译。`decidable: rule` 的项可以自动处理（高风险操作仍需审阅）。

**阶段 0 求解报告里的冲突代码**（阶段 1 由协作层转成待决项）：

| code | blocking | 含义 |
|---|---|---|
| `intent_over` / `intent_under` | 是 | 全片超出 L4 上限 / 短于下限，弹性已用尽 |
| `fixed_exceeds_source` | 是 | 固定长度超出素材 |
| `anchor_diverged` | 否 | 补丁的两种解释分开，按主锚点保留 |
| `unanchored` | 否 | 补丁找不到锚点，未应用、未丢弃 |
| `patch_out_of_range` | 否 | 剪切点不在片段内 |
| `rule_conflict` | 否 | 同样具体的规则覆盖同一片段 |
| `solver_changed` | 否 | 求解器版本和锁不一致 |

### 11.6 交接：AI 无状态
工程状态 = 文件 + 待决队列 + 草稿 + 任务日志。
新 AI 接入时固定调用 `onboard()`，依次读取：`AGENTS.md` → L0 摘要 → diff → 分给它的待决项 → 交接记录。

### 11.7 三种协作节奏
指令（马上做）· 委托（后台做，完成后提交变更集）· 巡检（主动发现问题，放进队列，不打断人）

## 12. AI 接口协议

### 12.1 原则
工具少、语法统一 · 每次返回都附下一步菜单 · 报错带修复方法 · 每次读取都有 token 上限 · 能力靠测出来，不靠模型自己声明

### 12.2 八个工具
| 工具 | 作用 |
|---|---|
| `onboard()` | 固定入口 |
| `view(target, depth, budget)` | 读任意层、任意范围；视图中标出挂了补丁的词 |
| `query(kind, ...)` | 检索素材和候选 |
| `inspect(target)` | 看拼板图、听音频片段，成本最高，单独计数 |
| `propose(ops, intent)` | 提交变更集，默认 dry-run |
| `commit(cs_id)` | 按风险等级生效，或进入审阅 |
| `queue(list/answer/ask)` | 读取和回答待决队列，也可以向人提问 |
| `lease(scope)` | 申请或释放租约 |

### 12.3 操作语法
动词 × 带类型的目标，不涉及时间码运算：
```
remove n:S2.3 · swap S2.b2.visual[0] → shot:C.08 · retext n:S2.1 "…"
move S3 after:S4 · set S2.budget 35s · generate image {…} slot:S2.b1 · answer q:17 A
brief S4.b2 {景别: 近, 主体: 手, 动作: 拧紧螺丝} · mark shot:B.12@+2.40s "进球"
add_rule {scope: …, do: …, examples: […]}     # 风险固定为中，批准前不生效
```
共 11 个动词：remove / swap / retext / move / set / generate / answer / brief / mark / add_rule / anchor（改锚点表达）。
乐观并发（必须带 `base`，版本过期就拒绝并返回 diff）· 提交幂等。

### 12.4 返回格式
```
S2 超出预算 3.8s（dry-run，未提交）
next: [1] commit cs:043  [2] propose remove n:S2.3 (-4.1s)  [3] candidates S2.b2
```
强模型可以自己组合操作，弱模型只需从菜单里选一项。

### 12.5 安全
转写、画面描述、文件名都是**数据，不是指令**。

## 13. 上岗考试（摘要）

详见《上岗考试题库 v0.5》。

- 考三件事：**不改坏**（一票否决，5/5 次都要过）· **听得懂**（每档通过率 ≥80%）· **做得好**（只作参考，不影响授权）
- 四档权限：T0 引导 / T1 低风险 / T2 中风险 / T3 结构，再加 X 陷阱题，共 28 题
- 尽量让机器判分：状态、不变量、过程、成本四类断言；授权链路不用模型判分
- 干扰器按覆盖式分配，考试种子可复现
- `decidable` 字段由系统自动推断，同时用来做题库自检
- 每道题记录“接口难度”（小模型失败率），以此衡量接口好不好用
- 人工抽检只用于找断言漏洞和比较质量；发现的问题必须转成自动断言

## 15. MVP 验证路径

**目的是先证伪风险最大的假设：**

| # | 假设 |
|---|---|
| H1 | 上提和补丁能保住人的改动 |
| H2 | 弱模型通过这套接口也改不坏工程 |
| H3 | 求解器确定、局部、有惯性 |
| H4 | AI 读懂一个项目只需要几千 token |
| H5 | 原生预览嵌进 Tauri 能做到 16ms（与阶段 0 并行验证） |

**样例**：混合解说片。用地球流水线的剧本和 TTS 做旁白主轴，地球基座作为确定型生成器插件接入，再加 10–20 个实拍 B-roll 片段走入库流程。

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| 0 无界面内核（3–4 周） | model / store / solver / compile / CLI / TTS 锁文件 | 幂等、顺序无关、局部性测试全部通过；改一个字只影响 ≤2 个区 |
| 1 AI 接入（3 周） | 8 个工具、变更集、待决队列、上岗考试 | 强弱两个模型做同一组任务，工程损坏率都是 0；完成“缩短 S2”消耗 < 5k token |
| 2 人类接手（4 周） | 脚本视图、简化时间线、上提和补丁、段落冻结、OTIO 导出 | AI 中途停掉后人能做完片子；人手动修改 10 处，0 处被静默丢弃 |

### 15.1 阶段 0 细化（D-5 已决）

**原则**：阶段 0 只测求解器和编译器，其他部分一律用确定的替身。不接真实 TTS、ASR、渲染，失败时才能定位到具体模块。

**已定**：
- 语言：**直接用 Rust**。确定性靠类型和整数刻度保证，不先写 Python 原型
- 黄金用例：**和代码放在同一个仓库**（`golden/` 目录），版本同步
- `clip view` 不进阶段 0，留到阶段 1 与 AI 接口一起做

### 15.2 阶段 0 实现规划

**原则**：阶段 0 只验证求解器确定、局部、有惯性。每个 PR 都必须能被黄金用例验证，所以最先完成的是测试框架，不是求解器。

#### crate 划分
```
clip/                       Cargo workspace
├ core-model     类型：Tick、语义 ID、各层结构、Cost、Report（纯数据，无 IO）
├ core-store     读写工程目录、引用校验、规范化输出、内容哈希
├ core-solver    盒子 + 胶水、分区、代价、冲突集（纯函数）
├ core-compile   L2→L1：锚点解析、补丁、规则、冻结，调用 solver
├ clip           CLI 二进制（8 个命令）
└ golden/        fx:min_explainer + 黄金用例目录
```
- 依赖只有一个方向：`model ← solver ← compile ← clip`；`store` 只被 `compile` 和 `clip` 使用
- `core-collab`、`core-render`、`core-otio` 阶段 0 不建

**求解器是纯函数**：
```rust
fn solve(input: &SolveInput, prev: Option<&SolveOutput>) -> SolveOutput
```
不读文件、不看时钟、不用随机数；惯性所需的“上次结果”通过 `prev` 显式传入。

#### 核心数据结构
```rust
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub struct Tick(i64);                       // flicks

pub struct WordId(..); pub struct ShotId(..); pub struct BeatId(..); // 带类型，不能混用
pub enum Anchor { Word(WordId), Event(EvId), Bar(BarRef), Mark(MarkId), Offset(ShotId, Tick) }

pub struct Glue { natural: Tick, stretch: Tick, shrink: Tick, kind: FitKind }

#[derive(PartialEq, Eq, PartialOrd, Ord)]   // 字段顺序 = §7.3 的字典序
pub struct Cost {
    hard: u32, human_lock: u64, intent: u64, meaning: u64,
    declared_budget: u64, cross_zone: u32,
    rate: u64, trim: u64, pause: u64, diff_from_prev: u64,
}
```
`Cost` 直接 `derive(Ord)`：**代价公式就是这个结构体的字段顺序**，调整顺序必须经过代码 review。

**确定性由编译期规则保证**：
- `core-solver` 开启 `#![deny(clippy::float_arithmetic)]`
- workspace 内禁用 `HashMap`/`HashSet`，统一用 `BTreeMap`/`BTreeSet`
- 时长字符串按十进制精确解析，不经过 f64

### 15.3 阶段 0 结果（v0.2）

| 项 | 结果 |
|---|---|
| 代码 | 5 个 crate（`core-model` / `core-store` / `core-solver` / `core-compile` / `clip`），求解器版本 `zone-6` |
| 测试 | 19 个黄金用例 + 单元测试，Linux / macOS / Windows 三平台逐字节一致 |

PR 顺序（实际）：PR 1 骨架 → PR 2 节拍求解 → PR 3 超时消化与分区 → PR 3.1 语速取整与开场/结尾保护 → PR 4 段落预算与偏短拉伸 → 阶段 0 收尾（锚点与补丁、规则/冻结/锁、CLI）。

**重点指标**（v0.1.4 补充：上提的统计同时区分“吸附到有名刻度”和“只能记素材偏移”）：人手动修改后，能上提的比例 vs 只能变成补丁的比例。
**MVP 不做**：调色、特效、多机位、混音（EQ、压缩、侧链等；音量 `level` 调整除外）、生图和生视频、Web 端、多人协作。

## 17. 风险汇总

| 风险 | 对策 |
|---|---|
| 上提规则覆盖不够，补丁泛滥 | 重点监控上提比例，不够就回头修改 L2 格式 |
| 拖动预演达不到 16ms | 增量求解只算当前区；用代理文件预览 |
| 约束无解或多解 | 最小冲突集上报；惯性和 ID 规则处理平局 |
| 下一步菜单限制强模型 | 菜单只是建议，强模型可以直接写操作 |
| 操作语法越加越多 | 每加一个动词，都要先过小模型的接口难度测试 |
| `AGENTS.md` 规则膨胀 | 定期整理，冲突的规则进队列由人裁决 |
| 审阅疲劳 | 变更集按段落拆小；抽检；高风险变更强制看对比播放 |
| 素材内容里藏指令 | 数据 / 指令隔离，考试中覆盖 |
| 召回质量取决于入库描述 | 入库描述格式固定：景别、主体、动作、环境 |
| 排序档位阈值 | 用样例工程校准 |
| 贪心顺序依赖 | 全局检查 + 待决队列修复 |
| TTS 生成前时长只能估算 | 两阶段编译；偏差在容差内不重排 |
| 事件检测不准 | 人工标记补充；检测模型版本写进索引 |
| 相似事件过多（如几十次射门） | 事件 ID 按素材位置分配不怕重复；关键事件靠人工标记区分 |
| 画面简述写错 | 属于创作，过字段合法性和段落目标一致性校验 |
| 重复检测误报 | 先只检测同一段落内同一种修改 |
| 规则越来越多 | 定期把相似规则合并，以建议形式交给人 |
| `alt` 记录长期占位 | 成本低，可接受 |
| 吸附加停顿代价 | 只在 ±0.3s 内、预算和 L4 允许时才做；不吸附的原因都写进报告 |
| 补丁不参与求解 | 裁剪后片段可能偏短；由检查报告提示，不反向影响求解 |
